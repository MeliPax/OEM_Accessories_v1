# VW vehicle database (CSV)

Everything here is generated by `python run_ingest.py` and `python run_accessories.py` (run from `source_code/VW`). Don't edit these files by hand: change `config/` and re-run.

| Folder / file | What it holds |
|---|---|
| `definitions/dim_category.csv` | The taxonomy levels: source, single or multi value, used for matching (from `config/categories.yaml`) |
| `definitions/dim_keyword.csv` | Every keyword and phrase, the category it fills and the value it stores (from `config/keywords.yaml`) |
| `definitions/dim_model.csv` | Make, models, submodels and series (from `config/models.yaml`) |
| `definitions/dim_option_set.csv` | Allowed values per model, submodel, year range and category (from `config/vehicles/*.yaml`) |
| `definitions/dim_resolution.csv` | Resolution rules, e.g. a lone `Black` -> `Black Edition` (from `resolutions:` in `config/keywords.yaml`) |
| `staging/stg_vw_models.csv` | Every source row as ingested (values untouched), plus `source_row`, `source_file`, `ingested_at` |
| `final/vehicles.csv` | One row per vehicle in the year window, with the description broken into taxonomy columns |
| `review/review_queue.csv` | Vehicles a person should check, one row per vehicle and issue (latest run) |
| `dq/ingest_runs.csv` | One row per run: window, row counts, parse coverage, flag counts |
| `dq/part_number_check.csv` | Accessories: one row per distinct (`stockCode`, how Excel stored it, `make&model`, model): the split (`make_model_part_number`, `make_model_model_name`), the result (`same`, `restored`, `mismatch`, `unexpected_characters`, `no_check_value`, `no_suffix`, `suffix_not_at_end`, `no_part_left`, `no_stock_code`), the part number used, the reason, rows and source rows. Written every run (idea 008) |
| `dq/accessory_lookup.csv` | Accessories: one row per (model, submodel, year) key: checks C1-C5 (vehicle DB rows, config years, known years, config status), the code if it missed, and the model numbers fetched |
| `review/accessory_review.csv` | Accessories: one row per part-year with no vehicle (`type = part`), per part number make&model restored or can't prove (`type = part_number`, rows in scope only), per suspect value (`type = value`: a labour time in the wrong unit, a link no rule covers) and per vehicle with no parts (`type = vehicle`), with code, severity, message, checked, found, causes, fix (latest run) |
| `dq/accessory_runs.csv` | Accessories: one row per run: row funnel, keys found / missed, matched rows, vehicles without parts, export file, flag counts |
| `logs/` | Run logs (git-ignored): `runs/<run_id>.log`, `steps.csv`, `changes/<run_id>.csv`, `flags/<run_id>.csv`. Run ids are `<pipeline>_<YYYYMMDD_HHMMSS>` |

## `final/vehicles.csv`

| Column | Meaning |
|---|---|
| `vehicle_id` | `VW-{model_year}-{model_number}`; unique, stable across runs |
| `make`, `model_number`, `model_year` | Key fields |
| `description_raw`, `description_clean` | As ingested / after aliases and repeated-word removal |
| `model`, `series`, `submodel` | From `models.yaml` (`series` is empty for most vehicles) |
| `trim` … `inventory_status` | One column per keyword category. Multi-value categories (`appearance_package`, `technology_package`, `body_style`) hold values sorted and joined with `\|`; read them with `parse_helpers.split_multi_value()` |
| `unparsed_tokens` | Words no keyword matched (empty when `parse_status = complete`) |
| `parse_status` | `complete`, `partial` (unknown words) or `failed` (no model found) |
| `source_file`, `taxonomy_version` | Lineage: the source file and a hash of the config that produced the row |

`inventory_status` is metadata and must never be used for matching (`use_for_matching = false`).

## Flag codes

Every flag carries a code from `config/messages.yaml`. Its message, causes and fix steps come from there, and the flag adds what was checked and what was found. The flags CSV, the review files and the run log all show these fields. Codes are `<PIPELINE>_<STAGE>_<WHAT>`: `CONFG_` config, `VEH_` vehicle ingest, `ACCESS_` accessories. The full scenario list is in `planning/ideas/004_error_message_catalogue_design.md`.

### Vehicle ingest (review queue)

| Code | Meaning | How to resolve |
|---|---|---|
| `VEH_PARSE_UNKNOWN_WORD` | A word no keyword matched | Add it to `config/keywords.yaml` |
| `VEH_VALID_OPTION_NOT_OFFERED` | A value outside the vehicle's option set | Add it to `config/vehicles/<model>.yaml` if it's real |
| `VEH_VALID_NOT_IN_CONFIG` | No option set covers the model / submodel / year | Add or extend an option set |
| `VEH_PARSE_CONFLICTING_VALUES` | Two values in a single-value category | Check the description; fix the keyword if it's wrong |
| `VEH_RESOLVE_SUGGESTED` | A resolution could apply (e.g. the same model number is `Black Edition` in another year), but the option set doesn't offer the value | Add the value to the option set if it's right |
| `VEH_RESOLVE_CONFLICT` | A resolution would set a single-value category that already has a different value | Check the description |
| `VEH_VALID_MODEL_NUMBER_REUSED` | A model number reused across years changes a field in `validation.model_number_consistency.compare` (default: model, submodel) | Check with the source. Trim / package / edition changes on a reused code are allowed and only noted in the run log |
| `VEH_WRITE_VEHICLE_REMOVED` | A vehicle in the previous `vehicles.csv` is gone | Check the new export |

### Accessories (`review/accessory_review.csv`)

| Code | Meaning |
|---|---|
| `ACCESS_LOOKUP_IN_CONFIG_NOT_IN_DB` | Config says the vehicle exists that year, but the vehicle DB has no model numbers: rerun the ingest / ask the source |
| `ACCESS_LOOKUP_YEAR_AFTER_LAST_KNOWN` | The accessory year is after the vehicle's last known year (discontinued, or not exported yet) |
| `ACCESS_LOOKUP_YEAR_BEFORE_FIRST_KNOWN` | The accessory year is before the vehicle's first known year |
| `ACCESS_LOOKUP_YEAR_IN_GAP` | The accessory year is missing between known years |
| `ACCESS_LOOKUP_IN_DB_NOT_IN_CONFIG` | The vehicle DB has it but the config doesn't declare the year (model numbers still attached) |
| `ACCESS_LOOKUP_MODEL_NOT_IN_DB` / `ACCESS_LOOKUP_NO_CONFIG_FOR_MODEL` | The model has no vehicles in any year / has no option set |
| `ACCESS_LOOKUP_UNKNOWN_MODEL_NAME` | The accessory model name isn't in `models.yaml` (add an alias or the model) |
| `ACCESS_COVER_VEHICLE_NO_PARTS` / `ACCESS_COVER_MODEL_NO_PARTS` | Vehicles in the DB that get no parts (for that year / in any year) |
| `ACCESS_STGNG_PART_NUMBER_RESTORED` | `stockCode` lost its leading zeros (stored as a number); the full number from `make&model` is used. Ask the source to export `stockCode` as text |
| `ACCESS_STGNG_PART_NUMBER_MISMATCH` | `make&model` holds a different part number, or one with characters outside `allowed_characters`; `stockCode` is kept |
| `ACCESS_STGNG_PART_NUMBER_UNVERIFIED_NUMBER` / `..._UNVERIFIED` | `make&model` can't prove the part number (empty, or doesn't end with the model name). Error when `stockCode` was a number (zeros may be lost), info when text |
| `ACCESS_STGNG_PART_NUMBER_INCONSISTENT` | One proven part number is written more than one way in `stockCode` |
| `ACCESS_STGNG_PART_NUMBER_SPLIT_RATE` | Fatal: more than `max_unproven_share` of rows can't be proven (the file layout probably changed) |

| `ACCESS_CLEAN_UNIT_SUSPECT` | A value looks like the wrong unit (e.g. 0.4 minutes of labour); still converted, confirm with the source |
| `ACCESS_CLEAN_UNREVIEWED_LINK` | A comment link no `link_rules` entry or `allowed_link_hosts` covers; kept as it is |

Part numbers are never padded: a number is only restored when `make&model` holds the zeros `stockCode` lost.

`ACCESS_CLEAN_UNKNOWN_TAG` (info, log only): a tag outside the configured tag lists was removed. Add it to `text_cleaning.separators.tags` or `remove_tags`.
