# VW vehicle database (CSV)

Everything here is generated by `python run_ingest.py` (run from `source_code/VW`). Don't edit these files by hand: change `config/` and re-run.

| Folder / file | What it holds |
|---|---|
| `definitions/dim_category.csv` | The taxonomy levels: source, single or multi value, used for matching (from `config/categories.yaml`) |
| `definitions/dim_keyword.csv` | Every keyword and phrase, the category it fills and the value it stores (from `config/keywords.yaml`) |
| `definitions/dim_model.csv` | Make, models, submodels and series (from `config/models.yaml`) |
| `definitions/dim_option_set.csv` | Allowed values per model, submodel, year range and category (from `config/vehicles/*.yaml`) |
| `definitions/dim_resolution.csv` | Resolution rules, e.g. a lone `Black` -> `Black Edition` (from `resolutions:` in `config/keywords.yaml`) |
| `staging/stg_vw_models.csv` | Every source row as ingested (values untouched), plus `source_row`, `source_file`, `ingested_at` |
| `final/vehicles.csv` | One row per vehicle in the year window, with the description broken into taxonomy columns |
| `review/review_queue.csv` | Vehicles a person should check, one row per vehicle and issue (latest run) |
| `dq/ingest_runs.csv` | One row per run: window, row counts, parse coverage, flag counts |
| `logs/` | Run logs (git-ignored): `runs/<run_id>.log`, `steps.csv`, `changes/<run_id>.csv`, `flags/<run_id>.csv` |

## `final/vehicles.csv`

| Column | Meaning |
|---|---|
| `vehicle_id` | `VW-{model_year}-{model_number}`; unique, stable across runs |
| `make`, `model_number`, `model_year` | Key fields |
| `description_raw`, `description_clean` | As ingested / after aliases and repeated-word removal |
| `model`, `series`, `submodel` | From `models.yaml` (`series` is empty for most vehicles) |
| `trim` … `inventory_status` | One column per keyword category. Multi-value categories (`appearance_package`, `technology_package`, `body_style`) hold values sorted and joined with `\|`; read them with `parse_helpers.split_multi_value()` |
| `unparsed_tokens` | Words no keyword matched (empty when `parse_status = complete`) |
| `parse_status` | `complete`, `partial` (unknown words) or `failed` (no model found) |
| `source_file`, `taxonomy_version` | Lineage: the source file and a hash of the config that produced the row |

`inventory_status` is metadata and must never be used for matching (`use_for_matching = false`).

## Review queue rules

| Rule | Meaning | How to resolve |
|---|---|---|
| `unknown_token` | A word no keyword matched | Add it to `config/keywords.yaml` |
| `not_offered` | A value outside the vehicle's option set | Add it to `config/vehicles/<model>.yaml` if it's real |
| `no_option_set` | No option set covers the model / submodel / year | Add or extend an option set |
| `single_value_conflict` | Two values in a single-value category | Check the description; fix the keyword if it's wrong |
| `resolution_suggested` | A resolution could apply (e.g. the same model number is `Black Edition` in another year) but the option set doesn't offer the value | Add the value to the option set if it's right |
| `resolution_conflict` | A resolution would set a single-value category that already has a different value | Check the description |
| `inconsistent_model_number` | A model number reused across years changes a field in `validation.model_number_consistency.compare` (default: model, submodel) | Check with the source. Trim / package / edition changes on a reused code are allowed and only noted in the run log |
