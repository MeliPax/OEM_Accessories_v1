## Phase 1: Configuration Changes (5 minutes)

### File: `accy_v2/model_lookup/configs/mitsubishi/classification.yaml`

**Current State (Lines 22-24):**
```yaml
  gt: TRIM
  GT Premium: TRIM
  gt-premium: TRIM
```

**Issue:** 
- `GT Premium` (title case) and `gt-premium` (hyphenated) are two separate entries
- But translator.yaml has `gt-premium: gt premium` and `gt-p: gt premium`
- So both should map to lowercase space-separated `gt premium`
- Title-case `GT Premium` is dead code for Mitsubishi (not generated by translator)

**Change to:**
```yaml
  gt: TRIM
  gt premium: TRIM
```

**Reasoning:**
- Both `gt-p` and `gt-premium` from translator output `gt premium`
- Single canonical form in classifier for lookup
- Removes redundant entries

## Phase 2: Contract Test (30 minutes)

### File: `accy_v2/model_lookup/tests/test_search_engine.py`

**Add new test function at end of file:**

```python
def test_mitsubishi_translator_classifier_contract():
    """
    Contract test: Every translator output must be recognized by classifier.
    
    Problem: Translator can output multi-word forms (e.g., 'plug-in hybrid')
    but classifier might not have them, causing tokens to drop silently.
    
    This test ensures the contract is maintained: if translator produces it,
    classifier can classify it.
    """
    import os
    from accy_v2.model_lookup.semantic.translator import Translator
    from accy_v2.model_lookup.semantic.classifier import Classifier
    
    # Load Mitsubishi configs
    configs_dir = os.path.join(
        os.path.dirname(__file__), 
        '../configs'
    )
    
    translator = Translator(
        oem="Mitsubishi",
        config_path=os.path.join(configs_dir, 'mitsubishi/translator.yaml')
    )
    classifier = Classifier(
        oem="Mitsubishi", 
        config_path=os.path.join(configs_dir, 'mitsubishi/classification.yaml')
    )
    
    # Test cases: (input, expected_category_after_translation)
    test_cases = [
        ("gt-p", "TRIM"),           # gt-p → gt premium → TRIM
        ("gt-premium", "TRIM"),     # gt-premium → gt premium → TRIM
        ("phev", "ENGINE_TYPE"),    # phev → phev stays → ENGINE_TYPE
        ("plug-in hybrid", "ENGINE_TYPE"),  # Already expanded → ENGINE_TYPE
        ("mhev", "ENGINE_TYPE"),    # mhev stays → ENGINE_TYPE
        ("hev", "ENGINE_TYPE"),     # hev stays → ENGINE_TYPE
        ("s-awc", "DRIVETRAIN"),    # s-awc → awc → DRIVETRAIN
    ]
    
    for input_token, expected_category in test_cases:
        # Step 1: Translate
        translated = translator.translate(input_token)
        
        # Step 2: Classify
        classified = classifier.classify_tokens([translated])
        
        # Step 3: Verify
        # The translated token should appear in the expected category
        found = False
        for token, category in classified.items():
            if token == translated and category == expected_category:
                found = True
                break
        
        assert found, (
            f"Translator output '{translated}' (from input '{input_token}') "
            f"not found in classifier category '{expected_category}'. "
            f"Full classification result: {classified}"
        )
```

**What this test does:**
- Takes real translator inputs
- Runs them through the translator
- Verifies the OUTPUT is recognized by the classifier
- Catches any future mismatches between translator outputs and classifier inputs

**Where to add it:**
- At the end of `test_search_engine.py`
- After existing tests like `test_search_exact_match_mitsubishi`, etc.

**How to run it:**
```bash
pytest accy_v2/model_lookup/tests/test_search_engine.py::test_mitsubishi_translator_classifier_contract -v
```

## Questions & Troubleshooting

**Q: What if the contract test fails?**  
A: The failure message shows which translator output isn't in the classifier. Add that token to `classification.yaml` with its category.

**Q: What if E2E run still shows NOT_FOUND cases?**  
A: Expected — not all NOT_FOUND cases are bugs. Use diagnostic reasons to distinguish data gaps (MODEL_YEAR_NOT_IN_DB) from matching failures (TRIM_VARIANT_NOT_FOUND).

**Q: Does this affect Hyundai or Genesis?**  
A: No. They have separate translator.yaml and classification.yaml files. This change only touches Mitsubishi's config.

**Q: Can we do this for Hyundai too?**  
A: Yes, but separately. Audit Hyundai's configs first to see if they have the same gap.
