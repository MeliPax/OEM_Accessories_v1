## Update 1: Exact Keyword Matching

### Problem
Model searches returned false positives. Searching for `["outlander", "phev", "gt"]` returned both:
- "Outlander PHEV GT S-AWC" (correct)
- "Outlander PHEV GT Premium S-AWC" (wrong - "premium" wasn't in search)

This caused false "Ambiguous match" DQ warnings.

### Solution
Implemented per-manufacturer vocabulary filtering with trim discriminator categorization:

**New files:**
- `model_lookup/configs/{make}_keywords.json` (10 files) — Vehicle descriptions tokenized and categorized
- `model_lookup/bootstrap_vocabs.py` — Script to generate vocab files
- `model_lookup/test_exact_matching.py` — 5 test cases validating exact matching

**Modified files:**
- `model_lookup/models/manufacture_module.py`:
  - Added `_extract_description_tokens()` — Whitespace tokenizer
  - Added `build_manufacturer_keyword_vocab()` — Generate vocab JSON
  - Added `load_manufacturer_keyword_vocab()` — Load vocab for search
  - Added `bootstrap_all_vocabs()` — Bootstrap all manufacturers
  - Added `_get_trim_discriminator_keywords()` — Categorize keywords as trim vs spec
  - Modified `search_models_by_description()` — Add post-filter logic
  - Modified `save_vehicle_models_to_csv()` — Auto-regenerate vocab on save

### How It Works
1. **Vocabulary files** contain all unique tokens from Description column
2. **Trim discriminators** (premium, noir, se, es, gt, le, limited, sport) identify trim levels
3. **Specifications** (fwd, awc, s-awc, manual, cvt, pkg) don't change trim level
4. **Post-filter** excludes results with extra trim discriminators, but allows extra specs

### Results
✅ `["outlander", "phev", "gt"]` → 1 result (GT S-AWC only)  
✅ `["outlander", "phev", "gt", "premium"]` → 1 result (GT Premium S-AWC)  
✅ `["rvr", "es"]` → 2 results (ES FWD + ES AWC)

## Update 2: model_lookup Migration to accy_v2

### Problem
`model_lookup` was at project root. Better to colocate with pipeline code.

### Solution
Moved `model_lookup/` into `accy_v2/model_lookup/`

**New location:**
```
accy_v2/model_lookup/
  ├── db/                      ← Vehicle model database
  ├── models/                  ← Search functions
  ├── db_queries/              ← Database queries
  ├── configs/                 ← Vocabulary JSON files
  └── ...
```

**Updated paths:**
- CSV defaults to: `Path(__file__).parent.parent / "db" / "db_vehicle_models.csv"`
- Configs defaults to: `Path(__file__).parent.parent / "configs"`
- Step4_5 CSV path: `Path(__file__).parent.parent.parent.parent / "model_lookup" / "db" / ...`

**Import compatibility:**
```python
# Both work:
from model_lookup.models.manufacture_module import search_models_by_description  # From accy_v2
from models.manufacture_module import search_models_by_description  # From model_lookup dir
```

**New files:**
- `accy_v2/model_lookup/__init__.py` — Package marker
- `accy_v2/model_lookup/models/__init__.py` — Subpackage marker
- `accy_v2/model_lookup/db_queries/__init__.py` — Subpackage marker

**Modified files:**
- `accy_v2/oems/mitsubishi/pipeline/step4_5_model_enrichment.py` — Updated CSV path
- `accy_v2/oems/mazda/pipeline/step4_5_model_enrichment.py` — Updated CSV path

**Tests:** All 7 migration tests pass ✓

See: [MIGRATION_MODEL_LOOKUP_2026-06-23.md](../MIGRATION_MODEL_LOOKUP_2026-06-23.md)
